# procura

Сервис закупок: сводит заказы клиентов и предложения поставщиков. В коде деньги и сотни запросов в секунду, поэтому ошибка стоит дорого.

Стек: FastAPI (async), MySQL, RabbitMQ, Redis. Админка: React + TypeScript. Прод: systemd + nginx, blue/green.

## Правила
@harness/RULES.md

## Порядок работы
1. Прочитай задачу: `python3 tools/task issue show --issue N`. Если требование неясно, спроси до кода.
2. Заведи дерево задачи `python3 tools/task wave start --issue N` и работай только в нём: одна задача — одно дерево — один MR.
3. Баг или мелкая правка: сначала тест, который воспроизводит проблему, потом фикс. Новая фича: короткий план, согласуй с человеком.
4. Код пишет `pc-implementer`, в дереве один писатель. Большие объёмы читает `pc-reader`.
5. Перед MR: `python3 tools/checks` зелёный, затем `pc-reviewer` на текущем HEAD.
6. MR создаёшь сам (`python3 tools/task mr create`). Вливает и деплоит только человек, ночью тоже.

Подробности — `harness/PIPELINE.md`.

## Остановись и напиши человеку, если
- тест или checks падает, а причина неясна;
- нужен новый пакет, миграция, деплой или доступ;
- нужного инструмента нет в каталоге;
- задача выходит за рамки одного MR;
- хук заблокировал команду. Обходить его другой формулировкой нельзя.

## Словарь: одно понятие — одно имя в коде
клиент — `Client` · поставщик — `Supplier` · заказ — `Order` · предложение поставщика — `Offer`

## Правила проекта

## Отчёт в конце задачи
- Сделано: 1–3 строки.
- Проверено: команды и их результат.
- Не проверено и риски.
